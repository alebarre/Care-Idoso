## Contexto

Atualmente a aplicação possui apenas login com e-mail e senha. Para melhorar a segurança e a experiência de onboarding/cadastro, precisamos implementar duas funcionalidades de autenticação auxiliar:

1. **Esqueci a senha** — usuário informa o e-mail cadastrado e recebe um código de 5 dígitos para redefinir a senha.
2. **Nova conta** — novo usuário informa seus dados e um e-mail, recebe um código de 5 dígitos para validar o e-mail antes de concluir o cadastro.

## Requisitos funcionais

### Backend (Spring Boot)

- Criar endpoints sob `/api/auth`:
  - `POST /api/auth/esqueci-senha` → recebe `email`, gera código de 5 dígitos numéricos e envia por e-mail.
  - `POST /api/auth/redefinir-senha` → recebe `email`, `codigo` e `novaSenha`; altera a senha (o código já foi validado na etapa anterior).
  - `POST /api/auth/validar-codigo` → recebe `email`, `codigo` e `tipo` (`ESQUECI_SENHA` ou `NOVA_CONTA`); valida o código e o invalida (one-time token).
  - `POST /api/auth/nova-conta` → recebe `nome`, `email`, `senha` e `perfil` (default `CUIDADORA`), gera código de 5 dígitos e envia por e-mail.
  - `POST /api/auth/validar-codigo-nova-conta` → recebe `email`, `codigo`; valida o código e ativa a conta.

- O código deve ser armazenado temporariamente com **TTL de 1 minuto**.
- Após a validação, o código deve ser invalidado (one-time token).
- Senha sempre criptografada com BCrypt antes de persistir.

### Envio de e-mail

- Implementar serviço de envio de e-mails (SMTP via Spring Mail).
- O e-mail deve conter:
  - Layout HTML moderno e elegante, inspirado no visual do app **Uber** (tipografia Inter, cores preto/branco, botões arredondados, espaçamento limpo).
  - Código de 5 dígitos em destaque.
  - Mensagem contextual diferente para **redefinição de senha** e **nova conta**.
  - Disposição de **cores diferentes** nos dois casos (fundo/preto para redefinição, tom sutil/verde para confirmação de nova conta).
  - Footer com a marca Care Idoso e instruções de segurança (não compartilhar o código).

### Frontend (Angular)

- Adicionar na tela de login links para:
  - "Esqueci a senha"
  - "Criar nova conta"

- Criar páginas seguindo o design system Uber já existente (`.uber-button`, `.uber-input`, `.page-screen`, `.page-header`):
  - **Esqueci a senha**: formulário de e-mail → tela de código → tela de nova senha.
  - **Nova conta**: formulário de dados → tela de código → confirmação/ativação.

- O código deve ter contador regressivo de 1 minuto com opção de reenviar.

### Banco de dados

- Criar migration Flyway `V3__codigos_verificacao.sql` com tabela `codigos_verificacao`.
- Migration `V4__codigos_verificacao_timestamptz.sql` altera `expiracao` e `created_at` para `TIMESTAMPTZ`, garantindo comparação de tempo sem ambiguidade de timezone.

## Critérios de aceitação

- [x] Usuário consegue solicitar redefinição de senha e receber e-mail com código de 5 dígitos.
- [x] Usuário consegue redefinir a senha informando o código correto dentro de 1 minuto.
- [x] Novo usuário consegue iniciar cadastro e receber e-mail com código de 5 dígitos.
- [x] Conta é ativada apenas após validação do código dentro de 1 minuto.
- [x] Código expirado ou já utilizado é rejeitado.
- [x] Código com menos de 5 dígitos ou com caracteres não numéricos é rejeitado.
- [x] E-mails possuem layout Uber-like com disposição de cores diferentes para cada fluxo.
- [x] Telas no frontend seguem o design system existente e possuem contador de expiração.
- [x] Build do frontend e backend passam sem erros.

## Observações

- Não commitar credenciais de SMTP no repositório; usar `.env`.
- Tokens/códigos nunca devem ser logados em texto claro (logs mostram apenas e-mail e tipo, nunca o código).
- Rate limiting simples implementado via cooldown de 60 segundos entre reenvios.
- Timezone da aplicação fixado em `America/Sao_Paulo`; armazenamento de expiração usa `Instant` + PostgreSQL `TIMESTAMPTZ` para evitar ambiguidade.
